1. 概述与架构

rks_extra 是一个 Minecraft 服务器安全数据包，提供五大核心功能：

模块功能核心原理
🔑 OP 泄露检测 检测玩家是否非法获得 OP 权限 每 tick 检查全体玩家的游戏模式、飞行权限、无敌状态、背包命令方块
📋 嫌疑人持久记录 NEW 记录嫌疑人信息，管理员上线后自动推送 持久计分板 + 上线检测 + 可点击交互命令
💣 TNT 用量管控 限制普通玩家每分钟 TNT 使用量 Minecraft 原生统计 + 快照比对，每分钟限 1 个，超量没收并归还
🏗️ 防爆区 保护指定区域不被 TNT 破坏 每 tick 遍历动态区域列表，自动清除区域内实体 TNT
💥 爆炸物检测 禁止在主世界使用末影水晶和 TNT 矿车 每 tick 检测 8 格内放置者 + 全局清理
📌 运行机制
数据包通过 #minecraft:tick 标签注册 rks_extra:tick 函数，每游戏 tick（0.05 秒）执行一次。 全局计数器 loop 每 200 tick（10 秒）轮转一次，周期警报在 loop=100 时触发（约每 5 秒）。

2. 快速上手（新服必读）

2.1 安装数据包

  1. 将 rks_security-26.2 文件夹放入世界存档的 datapacks/ 目录。
  2. 重启服务器或执行 /reload。
  3. 看到聊天栏显示 「已加载rks_extra数据包v1.2」即表示成功。

2.2 安装后第一件事：设置你自己为管理员

⚠️ 重要：加载数据包后，你的 OP 权限会立即被检测为"泄露"。必须在 5 秒内给自己打上管理员标签！ 
/tag <你的ID> add player
/tag <你的ID> add players

两条命令缺一不可——player 和 players 分别覆盖不同的检测项。如果只打一个，你仍然会被某些检测项标记。

✅ 验证是否成功：等 5~10 秒，如果不弹出 OP 泄露警报，说明设置正确。

2.3 设置其他管理员

/tag <玩家ID> add player
/tag <玩家ID> add players

2.4 （可选）设置爆炸信任玩家

如果你希望某些玩家不受 TNT 限制（例如建筑工），给他们打上信任标签：

/tag <玩家ID> add explosive_trusted
⚠️ 注意：explosive_trusted 不包含 OP 泄露检测豁免。信任玩家仍需单独打管理员标签。

3. 管理员白名单

管理员白名单使用两个被混淆命名的标签实现，恶意玩家很难意识到它们是管理员标记：

标签覆盖的检测项额外功能
player（单数） 创造模式 · 无敌状态(Invulnerable) · 背包命令方块 接收所有安全警报广播
players（复数） 旁观模式 · 飞行权限(mayfly) —
explosive_trusted —（不涉及 OP 检测） 绕过 TNT 数量限制 · 免于水晶/矿车检测

3.1 混淆策略说明

🔐 设计意图：player（玩家，单数）和 players（玩家们，复数）看起来像是"人人都有"的通用标签。恶意玩家即使通过某种方式查看到自己缺少某个标签，也只会以为是服务器遗漏——而不会意识到这是管理员白名单。两者分工不同，必须同时打上才能完全免疫 OP 泄露检测。

3.2 查看与维护

操作命令
查看某玩家的所有标签/data get entity <玩家> Tags
移除某玩家管理员身份/tag <玩家> remove player
/tag <玩家> remove players
移除爆炸信任/tag <玩家> remove explosive_trusted

4. OP 泄露检测

4.1 检测项详解

每 tick 对所有玩家执行以下五项检查。任一命中且缺少对应标签，则标记 good=1：

#检测条件所需豁免标签触发场景
1 gamemode=creative player 玩家处于创造模式
2 gamemode=spectator players 玩家处于旁观模式
3 abilities:{mayfly:1b} players 玩家拥有飞行权限（通常是 OP 获得）
4 Invulnerable:1b player 玩家处于无敌状态
5 背包含有 command_block player 玩家背包中有命令方块（通常只有创造+OP 能拿）

4.2 工作流程

每 tick → 遍历全体玩家 → 检查 5 项条件 → 命中且无标签？ → good=1 → 每 5 秒广播警报

4.3 警报格式

管理员会收到以下格式的告警消息：

[op泄露警报]
嫌疑玩家: <玩家ID>

多个嫌疑玩家会以逗号分隔列出。

4.4 处理流程

  1. 收到告警后，立即查看嫌疑玩家列表： 
    /scoreboard players list @a[scores={good=1}]
  2. 确认该玩家是否合法（例如是否是你刚设的管理员但漏打标签）：
  3. 如果是合法玩家：补打标签并清除标记 
    /tag <玩家> add player
/tag <玩家> add players
/scoreboard players set <玩家> good 0
  4. 如果是非法玩家：立即采取措施（封禁/撤销 OP 等），然后清除标记以停止重复告警： 
    /scoreboard players set <玩家> good 0
⚠️ 注意：good=1 只是标记，不会自动撤销玩家的 OP 或踢出玩家。你需要手动处置。如果不处理，警报会每 5 秒重复一次。

5. TNT 用量管控

5.1 核心规则

  • 普通玩家每分钟最多放置 1 个 TNT。
  • 拥有 explosive_trusted 标签的玩家不受限制。
  • 每 60 秒（1200 tick）全局重置所有玩家的 TNT 计数。

5.2 完整工作流程

Step 1 — 检测放置：
每 tick 比对 tnt_used（原生统计）与 tnt_prev（快照），不一致 → 判定为新放置。

Step 2 — 通知与计数：
→ 向管理员广播「XX 放置了TNT」
→ 非信任玩家 tnt_count + 1
→ 更新快照 tnt_prev = tnt_used
→ 若 tnt_count=1（首次），提示「服务器每分钟只能放置1个TNT」

Step 3 — 超量处置（tnt_count ≥ 2）：
→ 清除玩家周围 8×8×8 区域内所有已放置的 TNT
→ 警告玩家「服务器每分钟只能放置1个TNT」
→ 设置 tnt_return_cd = 2（启动归还倒计时）
→ tnt_count 重置为 1，tnt_restrained 标记为 1

Step 4 — 归还 TNT（冷却 2 tick 后）：
→ tnt_return_cd 倒计时：2 → 1 → 0
→ 归零时给予玩家 1 个 TNT，然后设为 -1（停止循环）

Step 5 — 全局周期重置（每 60 秒）：
→ 所有玩家 tnt_count 归零
→ tnt_restrained 标记清除
→ 全员提示「TNT限制已重置」

5.3 为什么要用"限制+归还"而不是"直接扣掉"

直接扣除 TNT 会让恶意玩家不断尝试。我们的策略是：

  1. 第 1 个 TNT：允许放置，但给予警告提示。
  2. 第 2 个 TNT：清除并警告，但不归还（已放置的 TNT 被没收）。
  3. 2 tick 后归还 1 个 TNT——保证善意玩家不会永久损失物品，同时让恶意玩家无法堆叠爆炸。

5.4 管理命令

操作命令说明
查看玩家 TNT 计数 /scoreboard players get <玩家> tnt_count 0=本分钟未使用, 1=已用一个, ≥2 会触发没收
手动重置某玩家 /scoreboard players set <玩家> tnt_count 0 立即将其 TNT 计数归零，本分钟可再放 1 个
手动触发全局重置 /function rks_extra:tnt_off 立即重置所有玩家的 TNT 计数（不等 60 秒）
查看玩家 TNT 使用统计 /scoreboard players get <玩家> tnt_used 原生统计，累计放置总数

5.5 相关计分板一览

计分板挂载目标含义
tnt_used每个玩家原生 TNT 放置统计（只增不减）
tnt_prev每个玩家上一次 tick 的 tnt_used 快照
tnt_count每个玩家当前分钟已用 TNT 数，≥2 触发没收
tnt_restrained每个玩家本分钟是否已被限制过（防重复处罚）
tnt_return_cd每个玩家归还冷却：0=归还, 1~2=等待, -1=已停止
tnt_timer#Global全局周期计时器，1200 tick（60秒）一轮

6. 防爆区管理

6.1 功能说明

防爆区是动态可配置的区域列表。每 tick 遍历所有区域，自动清除区域内已点燃的实体 TNT（不会阻止放置，但 TNT 点燃后立即被移除）。

区域数据存储在 storage rks_extra:storage tnt_free.areas，支持游戏内热编辑，无需重启或 /reload。

6.2 默认区域

首次加载时会自动设置 5 个默认防爆区。如果 storage 中已存在数据（例如你编辑后 /reload），不会覆盖。

6.3 管理命令

操作命令
查看所有防爆区 /function rks_extra:tnt_free_area/list
添加防爆区 /function rks_extra:tnt_free_area/add {x:<起点X>,y:<起点Y>,z:<起点Z>,dx:<X跨度>,dy:<Y跨度>,dz:<Z跨度>}
删除防爆区（按序号） /function rks_extra:tnt_free_area/remove {index:<序号>}
清空所有防爆区 /function rks_extra:tnt_free_area/clear
恢复默认防爆区 /function rks_extra:tnt_free_area/init
查看原始数据 /data get storage rks_extra:storage tnt_free.areas

6.4 使用示例

添加一个防爆区

例如保护出生点 (0, -64, 0) 到 (100, 320, 100) 的范围：

/function rks_extra:tnt_free_area/add {x:0,y:-64,z:0,dx:100,dy:384,dz:100}

参数说明：x,y,z 为区域起点坐标（含），dx,dy,dz 为从起点向正方向的跨度（含）。最终覆盖范围为 [x, x+dx] × [y, y+dy] × [z, z+dz]。

删除一个防爆区

先用 list 查看序号，然后按序号删除（序号从 0 开始）：

/function rks_extra:tnt_free_area/list           ← 查看所有区域及序号
/function rks_extra:tnt_free_area/remove {index:3}  ← 删除序号 3 的区域

重置为默认

/function rks_extra:tnt_free_area/clear
/function rks_extra:tnt_free_area/init
⚠️ 注意：防爆区只在主世界 (overworld)生效。末地、下界的 TNT 不受防爆区保护。

7. 爆炸物检测（水晶/矿车）

7.1 功能说明

该模块禁止在主世界使用末影水晶和 TNT 矿车——这两种实体可用于造成巨大爆炸破坏。检测分为两个层面：

层面机制频率
嫌疑人追踪 检测水晶/矿车 8 格范围内的非信任玩家，标记 explosive_suspicious + 1 每 tick
全局清理 无条件杀死主世界中的所有末影水晶和 TNT 矿车 每 tick

7.2 警报格式

[防爆警报] 有人试图在主世界放置末影水晶/TNT矿车！
嫌疑玩家: <玩家ID>

7.3 豁免机制

拥有 explosive_trusted 标签的玩家不会被标记为嫌疑人，但他们放置的水晶/矿车仍然会被全局清理（因为清理是无条件的）。

💡 设计意图：如果管理员确实需要在主世界使用水晶/矿车，需要临时移除相关检测逻辑。目前数据包没有提供开关——这确保了最高安全级别。

7.4 管理命令

操作命令
查看可疑爆炸玩家/scoreboard players list @a[scores={explosive_suspicious=1..}]
清除某玩家嫌疑/scoreboard players set <玩家> explosive_suspicious 0

8. 周期警报系统

8.1 时间线

tick 0 → loop=100 (5秒) → 📢 OP 泄露警报 → 📢 防爆警报 → loop=200 (10秒) → 🔄 loop 归零

8.2 警报接收者

所有带有 player 标签的管理员会收到警报。带 players 但无 player 的管理员不会收到警报。

8.3 两种警报对比

警报类型触发条件消息前缀频率
OP 泄露警报 存在任何 good=1 的玩家 [op泄露警报] 约每 5 秒（只要存在嫌疑玩家就持续）
防爆警报 存在任何 explosive_suspicious≥1 的玩家 [防爆警报] 约每 5 秒（只要存在嫌疑玩家就持续）
✅ 停止警报的方法：清除对应计分板即可。
OP 泄露 → /scoreboard players set <玩家> good 0
防爆 → /scoreboard players set <玩家> explosive_suspicious 0

9. 嫌疑人持久记录 NEW v1.2

9.1 解决的问题

旧版警报系统使用 @a[tag=player] 发送——管理员必须在线才能收到。如果管理员离线期间发生 OP 泄露或爆炸物事件，这些信息会永久丢失。

现在，嫌疑人信息会被持久记录在计分板中（玩家离线也不会消失）。管理员一上线就会收到通知。

9.2 工作原理

① 首次检测到违规 → 双重标记：
good=1（实时警报用，和以前一样）
s_sus_op=1（持久记录，玩家离线也保留）
同时计数器 #suspicious s_sus_op +1

② 管理员上线 → 自动检测：
每 tick 检查 s_online 状态变化
检测到管理员新上线 → 触发 on_join 函数

③ 推送积压记录：
检查计数器是否有积压 → 向管理员显示在线嫌疑人列表
提供可点击的 [查看详情] 和 [清除记录] 按钮

④ 管理员处置后清除：
运行 /function rks_extra:suspicious_clear
使用 * 通配符清除所有玩家（含离线）的标记和计数器

9.3 上线通知示例

管理员上线后，如果存在积压记录，会看到：

[rks_extra] ⚠️ 自上次检查以来的嫌疑人记录：
  OP泄露: Player1, Player2
  爆炸物: Player3
💡 使用 /function rks_extra:suspicious_list 查看详情  /function rks_extra:suspicious_clear 清除记录
💡 注意：上线通知中只显示当前在线的嫌疑人姓名。如果嫌疑人已离线，计数器仍会记录数量，但名字不会出现在通知中。离线嫌疑人的记录不会丢失——他们上线后会重新出现在 suspicious_list 中。

9.4 与实时警报的关系

机制触发时机覆盖场景
实时警报（旧） 每 5 秒，管理员在线 + 嫌疑人在线 管理员正在服务器上时
持久记录（新） 管理员上线时，一次性推送 管理员离线期间发生的事件

两者互补，不会重复。实时警报负责"正在发生"，持久记录负责"曾经发生"。

9.5 管理命令

操作命令说明
查看嫌疑人记录 /function rks_extra:suspicious_list 显示在线嫌疑人的交互式列表（含清除按钮）
清除所有记录 /function rks_extra:suspicious_clear 清除所有（含离线）玩家和计数器，重置为干净状态
查看原始 OP 嫌疑数据 /scoreboard players list @a[scores={s_sus_op=1..}] 仅在线玩家
查看原始爆炸嫌疑数据 /scoreboard players list @a[scores={s_sus_exp=1..}] 仅在线玩家
查看嫌疑人计数 /scoreboard players get #suspicious s_sus_op
/scoreboard players get #suspicious s_sus_exp		 显示累计检测次数（含已离线玩家）

9.6 典型工作流

  1. 周末离线：玩家 A 在周六非法获得 OP → 被标记 s_sus_op=1
  2. 周一上线：管理员登录 → 立即看到通知「自上次检查以来的嫌疑人记录」
  3. 查看详情：点击通知中的命令或手动运行 /function rks_extra:suspicious_list
  4. 处置：封禁玩家 A，运行 /function rks_extra:suspicious_clear 清空记录
✅ 最佳实践：每次处置完嫌疑人后，运行 /function rks_extra:suspicious_clear 清空记录。这样下次上线时如果又有通知，你就知道是新事件。
⚠️ 注意：如果你上线后没有收到通知，但有玩家告诉你之前发生过可疑事件，手动运行 /function rks_extra:suspicious_list 即可查看——通知只在计数器 > 0 时发送，如果计数器因某种原因未更新（如旧版升级），手动查看仍然能看到 s_sus_op=1 的在线玩家。

10. 计分板参考

名称类型挂载目标真实含义
good dummy 嫌疑玩家 OP 泄露嫌疑标记。1 = 已被抓获。
s_joined dummy 所有玩家 玩家初始化标记。1 = 已初始化记分板。
loop dummy #Global 全局 tick 计数器，0→200→归零 循环。
tnt_used minecraft.used 所有玩家 原生 TNT 放置统计，每放置 1 个自动 +1。
tnt_prev dummy 所有玩家 上次 tnt_used 快照，用于比较检测新放置。
tnt_count dummy 所有玩家 当前周期 TNT 已用数。≥2 触发没收。
tnt_timer dummy #Global 全局 TNT 周期计时器，1200 tick 触发重置。
tnt_restrained dummy 所有玩家 本周期是否已被没收过。1 = 已限制。
tnt_return_cd dummy 所有玩家 归还 TNT 冷却倒计时：2→1→0（归还）→-1（停止）。
explosive_suspicious dummy 嫌疑玩家 水晶/矿车放置嫌疑计数。≥1 触发防爆警报。
tnt_free_idx dummy #tnt_free_idx 防爆区遍历索引（内部使用）。
calc dummy #_cx 等假玩家 中间计算用（内部使用）。
s_online NEW dummy 所有玩家 在线状态追踪。1 = 上一 tick 在线。用于检测玩家上线/重新上线。
s_sus_op NEW dummy 嫌疑玩家 OP 泄露持久标记。1 = 曾检测到 OP 泄露。离线不消失，由管理员手动清除。
s_sus_exp NEW dummy 嫌疑玩家 爆炸物持久标记。1 = 曾检测到水晶/矿车放置。离线不消失，由管理员手动清除。

11. 排错指南

Q: 我自己触发了 OP 泄露警报

你忘了给自己打标签，或者只打了一个。执行：

/tag <你的ID> add player
/tag <你的ID> add players
/scoreboard players set <你的ID> good 0

Q: 警报一直在刷屏

说明有嫌疑玩家未被处理。先定位：

/scoreboard players list @a[scores={good=1}]

处置后清除标记即可停止警报。

Q: 玩家反映 TNT 被吞了

正常行为——玩家在 60 秒内放了第 2 个 TNT，第一个保留，第二个被没收但 2 tick 后归还。如果玩家持续被吞 TNT，检查：

  • 该玩家是否有 explosive_trusted 标签？如果没有，他们就是被限制了。
  • 是否 60 秒重置周期还没到？可以用 /function rks_extra:tnt_off 手动重置。

Q: 防爆区不生效

  • 确认区域在主世界（防爆区仅主世界有效）。
  • 用 /function rks_extra:tnt_free_area/list 检查区域是否正确。
  • 确认是实体 TNT（已点燃的），而非 TNT 方块。数据包只清除实体 TNT。

Q: /reload 后防爆区丢失

不会丢失。区域数据存储在 storage 中，/reload 会保留。只有 clear 命令或卸载数据包才会清除。如果使用 init 覆盖了你的自定义配置，那是你自己调用了 init 函数。

Q: 如何彻底关闭某个模块

数据包目前没有配置开关。如需关闭某模块，需直接编辑 tick.mcfunction 注释掉对应行：

  • 关闭 OP 检测 → 注释 function rks_extra:detect 行
  • 关闭 TNT 管控 → 注释 TNT 相关 5 行
  • 关闭防爆区 → 注释 function rks_extra:tnt_free_area 行
  • 关闭爆炸物检测 → 注释水晶/矿车检测和清理行

Q: 管理员上线没有收到嫌疑人通知

  • 确认计数器归零：/scoreboard players get #suspicious s_sus_op 和 s_sus_exp 都为 0 表示没有积压。
  • 确认你有 player 标签：只有带此标签的管理员才会收到通知。
  • 手动查看：运行 /function rks_extra:suspicious_list 随时查看记录。
  • 如果是旧版升级到新版，之前的数据没有 s_sus_op / s_sus_exp 标记，需要等新事件触发才会记录。

Q: suspicious_list 显示的嫌疑人比我预期的少

suspicious_list 使用 @a 选择器，只能显示当前在线的嫌疑人。已离线的嫌疑人虽然记录保留在计分板中，但无法通过 tellraw 显示名字。检查计数器可确认总数：

/scoreboard players get #suspicious s_sus_op
/scoreboard players get #suspicious s_sus_exp
